# RoboMaster 战术对抗模拟系统 · 设计文档

> 状态：**架构已定**；数值 / 场地 / 兵种属性标记为「待定」，最后一起填。
> 更新：2026-11-11

## 1. 项目概述

用 C++ 独立实现一个**离线回合制**机器人对抗程序。红蓝双方各有一个基地和若干机器人，在含障碍物与补给区的地图上轮流行动，直到一方基地被摧毁，或到达回合上限。核心对战逻辑用 C++ 的封装 / 继承 / 多态实现；图形用 EasyX 仅作展示。

## 2. 分层架构（核心设计）

分三层，规则只存在于模型层，图形只在视图层：

```
┌──────────────────────────────────────────────────┐
│ 模型层 = 裁判（核心逻辑，不依赖图形，可独立测试）    │
│   common(Team/Pos)  Robot 抽象基类 + 3 子类         │
│   Base   Map   Game   Logger                       │
├──────────────────────────────────────────────────┤
│ 视图层 = 转播（EasyX，只画图、只读操作，不裁决）      │
│   Renderer（画）   Input（读操作）                  │
├──────────────────────────────────────────────────┤
│ 组装：main.cpp（把两层接起来，跑主循环）              │
└──────────────────────────────────────────────────┘
```

**为什么分层**：
1. 模型层可以脱离窗口，先在黑窗口 `cout` 打印就能测规则对不对。
2. 视图层不碰规则，改图形绝不会改坏逻辑 → 对应任务书"第三方库仅辅助，不得代替核心对战逻辑"。
3. 规则全部集中在 `Game`，合法性只有一道闸，才能做到"非法输入不得绕过规则"。

## 3. 类清单与职责

| 类 | 职责 | OOP 要点 |
|---|---|---|
| `common.h` | `Team` 枚举、`Pos` 坐标、`manhattan()` 距离 | 公共类型 |
| `Robot` | 抽象基类：藏状态 + 声明纯虚能力接口 | 封装 + 多态底座 |
| `Infantry` / `Sniper` / `Engineer` | 各自 override 射程 / 移动 / 伤害 / 修理 | 继承 + 多态 |
| `Base` | 基地：只有 HP + 阵营 | 封装 |
| `Map` | 战场：格子类型、占位、越界 / 障碍判断 | 封装（占位唯一来源） |
| `Game` | 裁判：回合流程、合法性校验、结算、终局判定 | 封装（规则集中） |
| `Logger` | 把每步行动 + 状态变化写进对局记录文件 | 封装 + 文件 I/O |
| `Renderer` | 把 Game 状态画成 EasyX 图 | 视图 |
| `Input` | 读玩家选择（行动类型 + 目标） | 视图 |

**位置归谁管**：机器人的位置不由 Robot 自己存，而是 Map 统一记录"谁站在哪格"。这样"占位"只有一个权威来源，移动 / 占位不会出现两处数据对不上。

## 4. 数据流（一个回合）

```
main 主循环
 └─ 每回合：
     ├─ 红方阶段：Game 让玩家依次选红方每台存活机器人的行动
     │    └─ 选行动 → Game 校验合法性 → 合法则结算并写 Logger → Renderer 重画
     ├─ 蓝方阶段：同理
     └─ Game 检查终局（基地被毁 / 到回合上限）
```

## 5. 规则骨架（数值「待定」）

> 这里只定"机制"，具体数字最后一起填。

- **行动顺序**：一回合 = 红方阶段 + 蓝方阶段（先后待定，暂定红先）。阶段内，玩家为每台存活机器人依次选择行动。
- **行动额度**：每台机器人每回合 1 次行动（待定）。行动类型：移动 / 攻击 / 补给 / 修理 / 待机。
- **合法性**（一律由 Game 校验，不合法给出明确反馈并要求重选）：
  - 移动：目标格在 `moveRange()` 内、非障碍、非基地、无人占、不越界；移动按格逐步走，途中每格都须可通行。
  - 攻击：目标（敌机器人或基地）在 `maxRange()` 内，且当前有弹药。
  - 补给：机器人须位于补给区，执行"补给"行动（该行动本身即代价），恢复量待定。
  - 修理：仅工程兵；目标为射程 1 内的存活友军；恢复量待定。
  - 待机：总是合法。
- **障碍与占位**：由 Map 统一判断。障碍格不可进入、不可停留；一格同一时刻最多一个单位。
- **攻击与补给**：伤害 = 攻击力（是否减防御待定）；每次攻击弹药 −1；补给恢复弹药 / HP（数值待定）。
- **阵亡处理**：HP ≤ 0 判阵亡，从战场移除，其所在格释放，之后不再行动、视为空。
- **终局判定**：
  - 基地 HP ≤ 0 → 该方判负，本局立即结束。
  - 到达回合上限（待定）→ 比较双方基地剩余 HP，高者胜；相等判平。
- **边界情况（须唯一结果，最后逐条补全）**：越界、目标是自己人、没弹药仍攻击、移动超范围、攻击超射程、对已阵亡单位行动、目标格被占、双方基地同回合同时被毁……每条都要有唯一处理，不崩溃、不越界、不产生负资源。

## 6. 与任务书对应

| 任务书要求 | 落点 |
|---|---|
| 必做 1 战队与机器人 | `Robot` + 3 子类 + `Base` |

| 必做 3 交互与裁决 | `Game`（裁决）+ `Input` / `Renderer`（交互） |
| 必做 4 结束与记录 | `Game` 终局判定 + `Logger` |
| 封装 / 继承 / 多态 | 分别由 Robot（封装 / 多态）、3 子类（继承 / 多态）承担 |
